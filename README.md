# Modular Workspace 3.3 — плагин администратора сети

Основа: Modular Workspace 3.2 (Material 3, PIN, SQLite, динамические `.mcrm` плагины).

## Что добавлено

- `plugins/sysadmin.mcrm` — декларативный плагин «Инструменты сисадмина» версии 1.0.0. Устанавливается через меню приложения. Зависимости: `crm` и `hardware`.
- Новый раздел **Сеть**: ICMP-like ping через Android `InetAddress.isReachable`, поиск подсетей IPv4 среди активных интерфейсов, поиск устройств (ICMP и TCP 80/443/22/445/3389, максимум 254 адреса выбранной локальной /24 или более узкой подсети), TCP сканирование списка до 64 портов, Wake-on-LAN по MAC через UDP magic packet.
- Раздел **Мониторинг**: проверка сервера клиента (через `hardware.devices`) по ICMP, TCP, UDP, HTTP и HTTPS, с параметрами порта, пути и ожидаемого HTTP-кода. `host_override` перекрывает адрес оборудования. При отсутствии переопределения локальный IP имеет приоритет над публичным.
- Раздел **Журнал**: время, результат и подробности последней проверки.
- Автоматический мониторинг через Android WorkManager (период от 15 минут, фактическое исполнение может задерживаться системой); уведомление о переходе из другого состояния в `Недоступен`.
- На экране сетевых инструментов: ручная проверка настроенных серверов и фильтр по клиенту.
- `plugins/hardware.mcrm` обновлён до 1.1.0: к карточке оборудования добавлено поле `public_ip` (публичный IP / DNS).

## Важные технические детали

`.mcrm` — ZIP с `manifest.json`. Сетевой код **не хранится в плагине**: все нативные операции реализованы в ядре `NetworkDiagnostics.kt`, а плагин объявляет страницу `{"kind":"native_tool","tool":"network"}`. Эта страница разрешена только плагину `sysadmin`. Для нового сетевого инструментария нужен **новый APK ядра**, дальнейшие изменения его декларативных страниц возможны через файлы плагинов.

Мониторинг привязан к записи оборудования `hardware.devices` с обязательным `client_id` владельца. IPv4 интерфейсы выявляются через `NetworkInterface`. Для сканирования требуется быть подключённым к соответствующей сети; VPN и мобильные сети могут иметь ограничения. В результатах обнаружения показаны узлы, ответившие на ICMP, или с открытыми TCP 80/443/22/445/3389; это не полный ARP/ICMP discovery.

UDP проверки без ответа **не считаются доказательством недоступности**, потому что UDP не требует ответного пакета. `InetAddress.isReachable()` зависит от ограничений Android и может возвращать неопределённый результат на доступном хосте. HTTP проверяет ровно указанный статус-код и не переходит автоматически по редиректу. Настройка HTTP без TLS потенциально небезопасна: не передавайте секреты в URL.

Проверки запускаются с телефона, а не с сервера наблюдения. Для мониторинга публичного IP требуется доступ к интернету; для локального IP — доступ к сети клиента (например, через VPN). Работа смартфона в Doze/с выключенным доступом к сети может задерживать проверки. События последних проверок сохраняются в SQLite; периодическое удаление старых записей пока не предусмотрено. Уведомления Android 13+ требуют разрешения.

Запускайте поиск и сканирование только в своих сетях или при разрешении владельца.

## Установка / обновление

1. Загрузить проект в GitHub, запустить `.github/workflows/android.yml`, установить `app-debug.apk`.
2. Убедиться, что в «Плагины» присутствуют `crm` и `hardware`.
3. Если hardware уже установлен: импортировать `plugins/hardware.mcrm` версии 1.1.0. Существующие записи сохраняются.
4. Импортировать `plugins/sysadmin.mcrm` в менеджере плагинов.
5. В оборудовании выбрать клиента, указать имя, тип и локальный или публичный IP. В «Мониторинг» добавить проверку соответствующего устройства.

Это сборочный исходный проект. Полный тест компиляции и реальная проверка на Android здесь не проводились. Без установленного Android SDK нельзя подтвердить успешный APK.
